### 「Loop 工程」爆火：Andrew Ng 拆解 AI 原生开发的三层循环

- **板块**：Skills 生态
- **来源**：X/@AndrewYNg
- **链接**：https://x.com/AndrewYNg
- **TitleEN**：Andrew Ng Breaks Down 3 Core Loops for AI-Native Product Development

Claude Code 创始人 Boris Cherny 和 OpenClaw 创始人 Peter Steinberger 推广的「Loop 工程」概念走红后，吴恩达系统阐述了 0-to-1 产品构建的三层循环：Agent 编码循环（分钟级）、开发者反馈循环（小时级）、外部用户反馈循环（天/周级）。核心洞察：人类的「上下文优势」决定了 human-in-the-loop 暂时不可替代。

- **EN**：After 'loop engineering' went viral from Claude Code and OpenClaw creators, Andrew Ng systematically defines three nested loops for 0-to-1 AI product building: the fast agentic coding loop (minutes), the developer feedback loop (hours), and the external user feedback loop (days/weeks). Key insight: humans retain a context advantage AI systems can't yet replace.

### 多 Agent 系统中验证延迟会引发「信念震荡」：有最优校正器位置

- **板块**：AI 论文
- **来源**：HuggingFace Papers
- **链接**：https://huggingface.co/papers/2606.27409
- **TitleEN**：Delayed Verification Causes Belief Oscillation in Multi-Agent LLM Networks

研究发现：在多 Agent LLM 系统中，如果验证/纠错 Agent 的响应太慢，错误信念会像病毒一样在 Agent 网络中扩散，甚至让整个系统陷入「振荡」而非收敛到正确答案。论文给出了稳定性阈值公式，并找到了「校正器 Agent 最佳放置位置」——对正在构建多 Agent 流水线的开发者有直接指导价值。

- **EN**：This paper shows that in multi-agent LLM pipelines, delayed verifier responses allow hallucinations to propagate and can cause the entire network to oscillate rather than converge. The authors derive a closed-form stability threshold and identify optimal corrector placement — directly useful for developers architecting multi-agent systems with quality-check nodes.

### SWE-Together：首个基于真实用户对话的多轮编程 Agent 基准测试

- **板块**：AI 论文
- **来源**：HuggingFace Papers
- **链接**：https://huggingface.co/papers/2606.29957
- **TitleEN**：SWE-Together: Multi-Turn Coding Agent Benchmark From Real User Sessions

现有编程 Agent 评测大多是「一次性任务」，而真实开发场景需要多轮澄清和迭代。SWE-Together 从 11,260 条真实用户-Agent 会话中提炼出 109 个仓库级任务，构建了首个多轮交互式编程 Agent 基准。对于在产品中集成 AI 编程助手的开发者，这个基准能更真实地反映实际性能。

- **EN**：SWE-Together introduces the first multi-turn coding agent benchmark built from 11,260 real user-agent sessions, covering 109 repository-level tasks. Unlike static benchmarks, it captures the iterative, clarification-heavy nature of real coding assistance — giving developers a much more realistic signal when evaluating AI coding tools.
