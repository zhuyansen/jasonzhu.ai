### OpenForgeRL：首个支持 Claude Code 类推理框架端到端训练的开源 RL 框架

- **板块**：AI 论文
- **来源**：HuggingFace Papers
- **链接**：https://huggingface.co/papers/2607.21557
- **TitleEN**：OpenForgeRL: First Open RL Framework for Training Harness-Native Agents

Claude Code、Codex 等 Agent 依赖复杂的「推理框架（harness）」驱动多轮工具调用，但现有 SFT/RL 训练栈无法原生支持这类有状态的多进程推理过程。OpenForgeRL 填补这一空白——对开发者意味着：你现在可以在自己的环境里端到端地训练和优化类 Claude Code 的 Agent，而不必依赖闭源基础设施。

- **EN**：Agents like Claude Code rely on complex inference harnesses that existing RL training stacks can't natively handle. OpenForgeRL is an open-source framework that lets developers train harness-based agents end-to-end in any environment — meaning you can now fine-tune Claude Code-style agents on your own infra without closed-source dependencies.

### Multi-Turn On-Policy 蒸馏新方法：大幅降低 Agent 训练成本

- **板块**：AI 论文
- **来源**：HuggingFace Papers
- **链接**：https://huggingface.co/papers/2607.04763
- **TitleEN**：ReOPD: Cheaper Multi-Turn Agent Distillation via Prefix Replay

训练多轮 Agent 最贵的地方在于每次更新都要重新跑环境交互和调用教师模型。ReOPD（Replayed-Prefix On-Policy Distillation）提出「离线环境」替代方案：复用预收集的教师轨迹作为前缀，让学生模型只在关键步骤在线采样。对需要持续微调 Agent 的开发者来说，可显著降低训练计算成本。

- **EN**：Training multi-turn agents is expensive because every update requires fresh environment rollouts and teacher model calls. ReOPD reuses pre-collected teacher trajectories as replayed prefixes, letting the student model only sample online at critical steps — significantly cutting training compute costs for developers building and fine-tuning agentic systems.

### FinanceComplexQA：专为 Agent 处理工业级金融文档设计的推理基准

- **板块**：AI 论文
- **来源**：HuggingFace Papers
- **链接**：https://huggingface.co/papers/2607.19238
- **TitleEN**：FinanceComplexQA: Agentic Reasoning Benchmark on Industrial Financial Documents

论文提出 Finance-LaTeX SKILL 和 FinanceComplexQA 基准，专门测试 Agent 在真实金融文档（复杂排版、大规模信息整合）上的推理能力。数据集含 2000 道专业问题，揭示不同 Agent 在实际金融分析任务中仍存在显著性能差距——对构建金融 AI 应用的开发者有直接参考价值。

- **EN**：FinanceComplexQA introduces a 2000-question benchmark testing AI agents on real industrial-grade financial documents with complex layouts. It reveals significant performance gaps between agents on genuine financial analysis tasks — directly useful for developers building finance AI applications who need to evaluate which models actually hold up under real-world complexity.
