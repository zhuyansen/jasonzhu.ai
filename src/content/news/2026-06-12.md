### HF 论文：ModSleuth 自动追溯现代 LLM 的「隐形依赖链」

- **板块**：AI 论文
- **来源**：HuggingFace Papers
- **链接**：https://huggingface.co/papers/2606.12385
- **TitleEN**：ModSleuth Audits the Hidden Dependency Chains Inside Modern LLMs

你训练的模型用了 A 模型生成的数据，而 A 又依赖 B 筛选语料——这条依赖链现在复杂到人类无法手动追踪。ModSleuth 提出自动审计框架，像软件 SBOM（物料清单）一样梳理 LLM 的上游依赖。对开发者而言，这意味着模型合规风险和「谁的能力在影响你的模型」将首次可被量化追溯。

- **EN**：ModSleuth introduces an automated framework to audit the recursive dependency chains in modern LLMs — tracking which upstream models generated training data, filtered corpora, or guided decisions. Think of it as an SBOM for AI models. Critical for compliance, IP risk, and understanding why your model behaves the way it does.

### HF 论文：ReVision 压缩截图 Token，让电脑操控 Agent 历史利用率大幅提升

- **板块**：AI 论文
- **来源**：HuggingFace Papers
- **链接**：https://huggingface.co/papers/2605.11212
- **TitleEN**：ReVision Cuts Screenshot Tokens, Letting Computer-Use Agents Use More History

电脑操控 Agent（如 Claude Computer Use）每步都要编码一张截图，长任务下 Token 爆炸，导致几乎无法利用历史信息。ReVision 利用「时序视觉冗余」——相邻截图变化不大这一事实——大幅压缩视觉 Token，首次让历史轨迹真正帮助提升 Agent 性能。对构建长流程自动化的开发者极具参考价值。

- **EN**：Computer-use agents waste massive tokens encoding near-identical consecutive screenshots. ReVision exploits temporal visual redundancy to compress visual tokens, finally enabling agents to meaningfully leverage interaction history. First method to show real performance gains from history in computer-use tasks — key for developers building long-horizon automation.

### HF 论文：SparDA 稀疏注意力架构，长上下文推理速度与内存双双突破

- **板块**：AI 论文
- **来源**：HuggingFace Papers
- **链接**：https://huggingface.co/papers/2606.04511
- **TitleEN**：SparDA: Sparse Decoupled Attention Breaks Long-Context Inference Bottlenecks

长上下文推理有两大痛点：KV Cache 随序列长度爆炸式增长、稀疏选择步骤本身复杂度仍是 O(T²)。SparDA 引入「Forecast」第四投影层，将稀疏选择与注意力计算解耦，同时缓解 PCIe 传输瓶颈。对于部署 128K+ 上下文模型的开发者，这是真正降低推理成本的硬核方案。

- **EN**：Long-context inference faces two walls: exploding KV cache memory and O(T²) sparse selection cost. SparDA introduces a fourth 'Forecast' projection to decouple sparse selection from attention computation, tackling both bottlenecks simultaneously. Directly relevant for developers deploying 128K+ context models who need lower inference costs.
