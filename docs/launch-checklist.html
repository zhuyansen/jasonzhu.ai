上线检查卡

任何功能上线（埋点、定时任务、数据管线、新页面、新接口）都按这张卡走完 G0–G6 七道关。每一步都写明动作、验证方法、通过标准。写法遵循 ASD-STE100 的原则：一句话只写一个动作，用祈使句，不写「尽量」「可能」。

总规则 代码写好了，不等于功能上线了。每一项都要在「数据终点」验证：数据真的进来了、邮件真的到了、接口真的拒绝了。 下面每一次事故，都是因为只验证了代码，没验证终点。

G2

开关与凭证

推送之后、验证之前
WARNING

代码里装了 SDK，不代表平台在收数据。控制台的开关要单独打开，单独验证。

  1. 打开每个平台的控制台开关。
    清单
    Vercel 项目 → Analytics → Enable；GA4 建媒体资源和数据流；Clarity 建项目。
    通过
    接口不再返回 not_enabled 这类错误。
  2. 用提示符存 secret，不用剪贴板命令。
    gh secret set NAME -R zhuyansen/jasonzhu.ai
    说明
    回车后在 ? Paste your secret 处粘贴。先复制 token、再复制命令，剪贴板会被覆盖。
  3. 检查 secret 的形状。
    验证
    跑一次用到它的 workflow。日报被拒时会报 token 长度、段数和异常字符。
    通过
    Vercel 以 vcp_ 开头、约 60 位；Clarity 是 JWT（eyJ 开头，3 段）。9 位、或含空格和 |，就是存错了。
  4. 确认套餐支持要用的功能。
    验证
    每个查询维度单独请求一次。
    通过
    没有 402。有 402，就删掉这个维度或者换数据源（例如 UTM 改用 GA4）。

G4

安全

涉及数据库或用户数据时
WARNING

NEXT_PUBLIC_* 的 key 会发到每个访客的浏览器里。它能读到的数据，等于所有人都能读到。

  1. 用 anon key 对每张含隐私的表查一次数量。
    curl -s -I -H "apikey: $ANON" -H "Authorization: Bearer $ANON" \
  -H "Prefer: count=exact" "$SUPABASE_URL/rest/v1/<表>?select=id&limit=0"
    通过
    返回 */0 或 401/403。返回真实数量就是泄露。只查数量，不拉数据。
  2. 检查新加的 RLS 策略。
    通过
    没有对隐私表写 FOR SELECT USING (true)。需要读的地方走服务端接口和 service key。
  3. 扫一遍提交内容里有没有密钥。
    验证
    git diff --cached | grep -iE "sk-|vcp_|eyJ|refresh_token"
    通过
    命中的只是代码里的字段名，不是真值。
G5

失败路径与产出抽检

自动化任务上线前
  1. 让上游出错一次，看任务怎么处理。
    验证
    给错 key，或者把接口地址改坏，跑一次。
    通过
    任务报错并停住，不推进进度、不写空结果。「出错」和「真的没有数据」必须分得开。
  2. 把降级条件覆盖到所有状态码。
    通过
    400、401、403、404、429、5xx、超时都有明确去向：换模型、换通道，或报错。
  3. 抽查 10 条产出。
    验证
    打开原始来源逐条比对。
    通过
    没有重复、没有转帖、没有张冠李戴。发现一类问题，就加一条代码层的结构检查（例如按媒体 ID 去重），不只改提示词。
G6

告警对账

日报、监控上线前
CAUTION

误报多了，真告警就没人看了。每条告警上线前，先和实际情况核对一次。

  1. 每条告警找一次真实情况核对。
    例子
    「KV 有 47 条待回灌」：逐条查过，47 条都已经在 Supabase，所以告警条件改成「KV 有、Supabase 没有」。
  2. 给依赖时间的告警加时间条件。
    例子
    快讯 cron 7:15 前才跑完，「今日快讯未出」只在北京时间 8 点后才报。
  3. 总数用平台给的总数，不自己加。
    例子
    GSC 按搜索词加总只有 7 次点击，按日期取是 96 次。Google 会隐去长尾查询。
